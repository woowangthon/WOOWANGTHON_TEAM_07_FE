# 개인별 출발 시간 계산

등록일: 2026-11-15 · REQ-TIME-008

## 입력 기준을 정한 이유

장애의 종류나 정도만으로 이동 시간을 정할 수 없다. 같은 사람도 오늘의 컨디션, 익숙한 역인지, 동행 여부에 따라 필요한 시간이 달라진다. 이 화면에서는 의료적 분류를 하지 않고 이번 이동에 필요한 시간을 묻는다. 휠체어·유모차·고령 등의 선택을 시간 배수로 바꾸지 않는다. 기존 온보딩의 도움 선택에서도 이동 시간을 추론하지 않는다.

사용자가 정확한 숫자를 모를 수 있으므로 추가 입력은 선택 사항이다. 기본 추정값과 적용 내역을 접힌 상태에서도 보여 주고, 필요한 사람만 상세 항목을 펼쳐 조정한다. 여유 시간은 5·10·15분 중 선택하거나 직접 입력한다. 이 선택지는 편의를 위한 값이며 검증된 장애별 권장 시간이나 정시 도착의 보장이 아니다.

## 입력과 계산 계약

| 화면에서 묻는 것 | FE 옵션 | 기존 BE 필드 | 기본값 | 허용값 |
|---|---|---|---|---|
| 출발 장소에서 역까지 이동 | `walkToStationMinutes` | `walk_to_station_minutes` | 7분 | 정수 0~120분 |
| 출발역 안에서 승강장까지 | `stationEntryMinutes` | `station_entry_minutes` | 3분 | 정수 0~120분 |
| 도착역 하차 후 목적지까지 | `exitWalkMinutes` | `exit_walk_minutes` | 3분 | 정수 0~120분 |
| 탑승 전 추가 여유 | `bufferMinutes` | `buffer_minutes` | 5분 | 정수 0~240분 |

이동에는 보행뿐 아니라 휠체어 등을 이용한 이동도 포함한다. 도착 희망 시각은 목적지 기준으로 해석한다. 하차 후 시간에는 출구까지와 출구에서 목적지까지를 함께 넣는다. BE의 기존 출구 이동 슬롯을 이 전체 구간의 추정 시간으로 활용하므로 별도의 목적지 좌표나 주소를 수집하지 않는다. 서버의 타임라인 이름에는 기존의 ‘출구 이동’ 표현이 남을 수 있다.

추정 계산은 희망 도착 시각에서 네 입력 시간과 서버 경로의 이동 시간을 뺀다. 시간표 열차를 고르는 경우 하차 후 시간을 반영해 열차를 고르고, 탑승 시각에서 역까지·역 안·추가 여유 시간을 빼서 출발을 계산한다. 실제 배차와 입력한 여유는 서로 다른 값이다. 목업에서는 기존 격자 배차 대기에 사용자가 입력한 여유를 추가 확보한다. 실데이터에서는 기존 BE `buffer_minutes` 슬롯으로 전달한다.

열차 주행 시간 자체에 사용자 속도 배수를 곱하지 않는다. 환승 구간별 개인 이동 시간은 기존 API에서 분리 입력을 지원하지 않으므로 이번 구현에서는 조정하지 않는다. 환승이 특히 오래 걸린다면 여유를 늘려 계획할 수 있지만, 그 값이 환승 열차 연결 가능성을 검증하는 것은 아니다. 전체 경로의 접근 가능성·엘리베이터 대기·혼잡·지연을 보장하지 않는다. 기존 서버 한계와 경고는 계속 표시한다.

## 오류·개인정보·결과

- 빈칸이나 소수, 음수, 최대값 초과를 기본값으로 조용히 바꾸지 않는다. 오류를 안내하고 해당 입력으로 포커스를 옮긴다. 0분은 허용한다.
- 입력을 바꾸면 이전 계산 결과와 진행 중 요청을 무효화한다. 다시 계산해야 변경값이 반영된다.
- 결과에는 계산 당시 네 값을 보여 준다. 기본값 복원을 명시적으로 제공한다.
- 진단명, 장애 등급, 보조기기 정보를 요구하지 않는다. 개인 시간은 화면 메모리에만 두고 별도로 브라우저 저장소나 DB에 저장하지 않는다. 계산에 필요한 네 숫자는 기존 출발 계산 API에 전송된다.
- React와 기존 `Prototype-v2` 화면에 동일하게 적용한다. BE·AI의 계약과 코드는 수정하지 않는다. 챗봇이 독립적으로 계산하는 출발 시간에는 이 화면의 개인값이 전달되지 않는다.

Chrome 재현: web에서 `node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 5181 --strictPort`로 서버를 켠다. 스크립트는 외부 요청을 차단하고 계산을 목업 모드로 명시 전환한다. 각 화면에서 320·375·768·1440px × normal·lg·xl·max의 16개 조합을 확인한다. 기본 접힘, 22분 입력 후 실제 계산 결과, 입력 변경 시 이전 결과 제거, 빈칸 제출의 오류와 포커스를 검증한다. 스크린샷은 `web/artifacts/departure-inputs/`에 생성되며 모바일 화면을 직접 확인했다. 작은 화면/큰 글자에서 복원 버튼이 넘치던 문제는 줄바꿈과 높이 조정으로 수정했다.

API 검증은 저장된 응답 fixture로 요청 본문을 검사했다. 0분·최대값 허용, 음수·소수·null·문자열 거부, 개인값 전달, 열차 이동 시간 유지, 자정 넘김과 이전 응답 무효화를 테스트했다. 실제 운영 서버·현장 이동·Safari/Firefox·스크린리더 음성은 이번에 검증하지 않았다. 처음 전체 테스트를 기본 병렬도로 실행할 때 기존 챗봇 음성 테스트 1개가 5초 타임아웃됐고, 해당 파일 단독 6개 및 worker 2개로 전체 77개 재실행은 모두 통과했다.
