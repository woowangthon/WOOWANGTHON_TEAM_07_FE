### REQ-CHAT-004 마이크로 말해서 질문하기 (받아쓰기, 자동 전송)

- 상태: 진행중 (구현·자동 검증 완료, 안드로이드 실기기 확인 대기)
- 우선순위: P1 (제안)
- 등록일: 2026-11-11
- 대상:
  - `Prototype-v2/index.html` `#chatForm` (`#chatInput`, 보내기 버튼)
  - `Prototype-v2/js/app.js` `initChat`, `sendChat`, `setChatDisabled`
  - `Prototype-v2/css/style.css` `.chat-form`, `.chat-composer`

**현재 문제**
챗봇에 질문하려면 글자를 입력해야 한다. 손이 불편하거나 작은 키보드가 어려운 고령자, 시각장애인에게는 입력 자체가 큰 장벽이다.

**요구사항**
1. 입력창 옆에 마이크 버튼을 둔다. 아이콘은 Material Symbols `mic`, 이름(`aria-label`)은 `말로 질문하기`. 누르는 영역 44px 이상.
2. 마이크 버튼을 누르면 받아쓰기를 시작한다.
   - 입력창이 "듣고 있어요…" 상태로 바뀌고, 마이크 버튼은 `■`(멈춤, `aria-label` `듣기 멈추기`)으로 바뀐다.
   - 말하는 동안 인식된 글자가 입력창에 실시간으로 채워진다.
   - 듣는 중임을 알 수 있게 버튼에 표시를 준다. 계속 반복되는 움직임은 쓰지 않고, 움직임 줄이기 설정에서는 색 변화만 쓴다. (REQ-MAP-003의 움직임 원칙과 같음)
3. 말을 멈추면(브라우저 음성 인식이 끝나면) 인식된 문장을 **자동으로 전송**한다. 사용자가 보내기 버튼을 다시 누르지 않아도 된다.
   - 전송된 문장은 지금처럼 사용자 말풍선으로 보인다. 잘못 인식되어도 사용자가 바로 알 수 있다.
   - 인식된 글자가 없으면 전송하지 않고 "잘 못 들었어요. 다시 말씀해 주세요." 안내를 입력창 근처에 잠깐 보여 준다.
4. 듣는 중에 `■`를 누르면 듣기를 멈추고, 그때까지 인식된 문장이 있으면 전송한다.
5. 마이크로 보낸 질문에는 "말로 물었다"는 표시를 남겨, 답변 읽어 주기(REQ-CHAT-005)가 이를 보고 동작한다.
6. 처음 쓸 때 브라우저가 마이크 권한을 묻는다. 거부하면 "마이크 권한이 필요해요" 안내를 보여 주고, 글자 입력은 그대로 쓸 수 있다.
7. 브라우저가 음성 인식(Web Speech API `SpeechRecognition`)을 지원하지 않으면 마이크 버튼을 숨긴다.
8. 인식 언어는 한국어(`ko-KR`)다.
9. 음성이 외부 서버로 전송될 수 있다는 안내는 설정·정보의 정보 구역에 둔다. (REQ-COM-001)

**완료 조건**
- [ ] 크롬에서 입력창 옆에 마이크 버튼이 있고, 지원하지 않는 브라우저에서는 보이지 않는다.
- [ ] 마이크를 누르고 "강남역 엘리베이터 돼?"라고 말하면 입력창에 글자가 채워지고, 말을 멈추면 자동으로 전송되어 답이 나온다.
- [ ] 듣는 중에 버튼이 멈춤 모양으로 바뀌고, 누르면 듣기가 멈춘다.
- [ ] 아무 말도 하지 않으면 전송되지 않고 다시 말해 달라는 안내가 나온다.
- [ ] 마이크 권한을 거부해도 글자 입력은 정상 동작한다.
- [ ] 화면 읽기 프로그램에서 마이크 버튼 이름이 상태에 맞게 읽힌다.

**참고**
- 2026-11-11 결정. 사용자가 음성 입력을 넣자고 하면서 "말로 질문하는게 받아쓰기로 채팅으로 들어가고 답변도 읽어주는 기능을 넣고 싶은데" 제안 → 논의 후 "말을 멈추면 자동 전송해줘. 괜찮네"로 결정.
- 자동 전송 이유: 손이 불편한 사용자가 한 번 더 누르지 않아도 되도록. 잘못 인식된 경우는 사용자 말풍선으로 확인할 수 있다.
- 관련: REQ-CHAT-005, REQ-COM-001, REQ-DS-006, REQ-DS-007

**작업 기록**

- 2026-11-15: React `ChatView`와 `voice/recognition/`에 구현했다. 첫 사용 고지·한국어 중간 결과·1회 자동 전송·수동 멈춤·권한/네트워크/무음 오류·화면 이탈 취소를 검증했다. 음성 입력 실패 시 작성 중이던 글자 질문을 보존한다.
- Fake 인식 테스트 13개와 통합 테스트를 통과했다. 버튼 접근성 이름과 크기는 DOM/Chrome에서 확인했으나 실제 마이크와 TalkBack 동작은 확인하지 않았으므로 위 실기기 완료 조건은 유지한다.
- 고지는 마이크 최초 사용 직전과 챗봇의 ‘음성 설정’에 둔다. 별도 설정·정보 화면(REQ-COM-001)은 이 작업에서 구현하지 않는다. [상세 동작·제약](../chat-speech-recognition.md), [안드로이드 확인 절차](../chat-voice-integration.md).

### REQ-CHAT-005 답변을 소리로 읽어 주기 ("말로 물으면 말로 답한다")

- 상태: 진행중 (구현·자동 검증 완료, 안드로이드 실기기 확인 대기)
- 우선순위: P1 (제안)
- 등록일: 2026-11-11
- 대상:
  - `Prototype-v2/js/app.js` `buildBotMsg`, `appendBotResponse`, `sendChat`
  - `Prototype-v2/js/ai-agent.js` 답변 객체(`resp`: `text`, `html`)에 읽어 줄 요약 추가
  - `Prototype-v2/css/style.css` `.msg.bot`

**현재 문제**
답변이 화면에만 나온다. 저시력자나 화면을 보기 어려운 상황(이동 중, 휠체어 조작 중)에서는 답을 확인하기 어렵다.

**요구사항**
1. 브라우저 음성 합성(`speechSynthesis`, 한국어 목소리)으로 답변을 읽어 준다.
2. 언제 읽는지 (설정 `답변 소리로 듣기`, REQ-COM-001)

   | 설정 | 마이크로 물었을 때 | 글자로 물었을 때 |
   |---|---|---|
   | `말로 물었을 때만` (기본) | 자동으로 읽음 | 읽지 않음 |
   | `항상` | 자동으로 읽음 | 자동으로 읽음 |
   | `끄기` | 읽지 않음 | 읽지 않음 |

   기본값을 "말로 물었을 때만"으로 둔 이유: 화면 읽기 프로그램(VoiceOver, TalkBack)을 쓰는 사용자에게 두 목소리가 겹치지 않게 하고, 지하철 안에서 갑자기 소리가 나지 않게 하기 위해서다.
3. 모든 봇 답변에 `🔊` 버튼(Material Symbols `volume_up`, `aria-label` `답변 듣기`)을 둔다. 설정과 상관없이 누르면 그 답변을 읽는다. (`끄기`여도 버튼으로는 들을 수 있다)
4. 읽는 동안 그 답변의 버튼은 `■`(`stop`, `aria-label` `읽기 멈추기`)으로 바뀌고, 누르면 멈춘다. 새 질문을 보내거나 마이크를 누르거나 다른 탭으로 가도 멈춘다.
5. 읽는 내용은 화면 글과 다르게 "듣기용"으로 만든다.
   - 답변 글(`text`) + 카드 대신 짧은 요약. 예: "강남역 엘리베이터 4대 중 3대 운행 중, 8-1번 출구 멈춤"
   - 카드 요약 문장은 운행 현황(REQ-COM-007)의 화면 읽기 문장과 같은 함수에서 만든다.
   - 시각은 "오후 여덟 시 오십삼 분"처럼, 노선 뱃지는 "2호선"처럼 읽히게 바꾼다.
   - 이모지, 기호(`·`, `→`, `↔`)는 읽지 않거나 말로 바꾼다.
   - 버튼 이름(`역 상세 보기` 등)과 추천 질문은 읽지 않는다.
6. 한국어 목소리가 없는 브라우저에서는 `🔊` 버튼을 숨기고 자동 읽기도 하지 않는다.

**완료 조건**
- [ ] 기본 설정에서 마이크로 "강남역 엘리베이터 돼?"라고 물으면 답이 자동으로 읽힌다.
- [ ] 기본 설정에서 글자로 물으면 읽히지 않고, `🔊`를 누르면 읽힌다.
- [ ] 설정을 `항상`으로 바꾸면 글자로 물어도 자동으로 읽힌다. `끄기`면 자동으로 읽히지 않는다.
- [ ] 읽는 중 `■`를 누르거나 새 질문을 보내면 읽기가 멈춘다.
- [ ] 출발 시각 답변에서 시각이 "오후 여덟 시 …"처럼 자연스럽게 읽히고, 기호나 이모지를 소리 내어 읽지 않는다.
- [ ] 역 카드가 있는 답변에서 카드 대신 한 문장 요약이 읽힌다.
- [ ] 한국어 목소리가 없는 환경에서는 `🔊` 버튼이 보이지 않는다.

**참고**
- 2026-11-11 결정. 논의에서 걸리는 점(화면 읽기 프로그램과 겹침, 지하철 안 소리, 화면용 글과 듣기용 말의 차이)을 정리하고 "말로 물으면 말로 답한다" 방식으로 결정. ("좋아.")
