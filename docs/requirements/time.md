### REQ-TIME-001 출발역·도착역을 검색해서 고르기

- 상태: 대기
- 우선순위: P1 (제안)
- 등록일: 2026-11-11
- 대상:
  - `Prototype-v2/index.html` `#originSelect`, `#destSelect` (`<select>`), `#swapBtn`
  - `Prototype-v2/js/app.js` `initTimeTab` (733행~, 역 목록 `<option>` 생성), `submitTime` (768행), `openTime` (851행~, `hasOption`), `onSheetAction`의 `calc-time` (534행~)
  - 재사용 후보: `Prototype-v2/js/app.js` `searchStations`, `normalizeName` (257~278행, 상단 검색)

**현재 문제**
출발역과 도착역을 기본 드롭다운(`<select>`)에서 고른다. 238개 역을 스크롤해서 찾아야 하고, 칸이 좁아 "신도림역 (…"처럼 이름이 잘린다.

**요구사항**
1. 출발역, 도착역 칸을 누르면 역 검색 바텀시트가 열려야 한다.
   - 맨 위에 검색창이 있고, 열리자마자 입력할 수 있다.
   - 역 이름 일부만 입력해도 결과가 나온다. (상단 검색과 같은 검색 규칙)
   - 결과 한 줄: 역 이름 + 노선 뱃지 + 엘리베이터 상태 아이콘(REQ-DS-003)
   - 검색 전에는 최근 고른 역(최대 5개)을 보여 준다. 최근 기록이 없으면 안내 문구를 보여 준다.
   - 결과를 누르면 그 역이 칸에 들어가고 시트가 닫힌다.
2. 칸에는 역 이름과 노선 뱃지가 잘리지 않게 들어간다. 길면 역 이름만 말줄임한다.
3. 출발·도착 바꾸기(`⇅`), 역 상세의 `이 역까지 출발 시각 계산`, 챗봇에서 넘어오는 값 채우기는 지금처럼 동작한다.
4. 출발역과 도착역이 같으면 지금처럼 안내한다.
5. 최근 고른 역은 브라우저에 저장한다.

**완료 조건**
- [ ] 출발역, 도착역 칸을 누르면 검색창이 있는 바텀시트가 열리고 바로 입력할 수 있다.
- [ ] "신도"를 입력하면 신도림역이 나오고, 누르면 칸에 들어간다.
- [ ] 결과에 노선 뱃지와 엘리베이터 상태 아이콘이 보인다.
- [ ] 한 번 고른 역이 다음에 열 때 최근 목록에 나온다.
- [ ] 375px 폭에서 칸 안의 역 이름이 "신도림역 (…"처럼 잘리지 않는다.
- [ ] `⇅`, 역 상세의 `이 역까지 출발 시각 계산`, 챗봇에서 넘어오기가 바뀌기 전처럼 동작한다.

**참고**
- 2026-11-11 결정. 사용자 원문: "내가 원한게 그거야. 검색 기능."
- 관련: REQ-COM-004 (바텀시트 두 단계 높이), REQ-DS-003, REQ-DS-006

### REQ-TIME-002 "도착 시각 맞추기 / 지금 출발"을 선택 버튼으로

- 상태: 완료
- 우선순위: P1 (제안)
- 등록일: 2026-11-11
- 대상:
  - `Prototype-v2/index.html` `#timeForm`의 `.switch` (`#modeNow`), `#arriveBy`
  - `Prototype-v2/js/app.js` `syncTimeMode` (728행), `submitTime`, `openTime`
  - `Prototype-v2/css/style.css` `.switch`

**현재 문제**
도착 시각 입력칸 옆에 "지금 바로 출발" 스위치가 있고, 켜면 시각 입력칸이 흐려진다. 두 가지 계산 방식 중 하나를 고르는 것인데 그게 잘 드러나지 않는다.

**요구사항**
1. 폼 맨 위에 두 칸짜리 선택 버튼을 둔다: `도착 시각 맞추기` | `지금 출발`.
2. 기본값은 `도착 시각 맞추기`다.
3. `지금 출발`을 고르면 도착 시각 입력칸을 숨긴다. (흐리게 두지 않는다)
4. 선택된 칸은 REQ-DS-001의 노랑 면 + 차콜 글자로 보여 준다.
5. 챗봇에서 "지금 출발" 조건으로 넘어오면 `지금 출발`이 선택된다. (지금 `openTime` 동작 유지)
6. 스위치(`.switch`)는 없앤다.

**완료 조건**
- [x] 폼 맨 위에 `도착 시각 맞추기` | `지금 출발` 선택 버튼이 있고, 처음에는 `도착 시각 맞추기`가 선택되어 있다.
- [x] `지금 출발`을 누르면 도착 시각 입력칸이 사라지고, 다시 `도착 시각 맞추기`를 누르면 나타난다.
- [x] 두 방식 모두 계산 결과가 바뀌기 전과 같다.
- [x] 챗봇에서 "지금 출발"로 넘어오면 `지금 출발`이 선택되어 있다.
- [x] 각 칸의 누르는 영역이 44px 이상이다.

**참고**
- 2026-11-11 추천안으로 결정. ("2. 그래. 좋아.")
- 관련: REQ-DS-001, REQ-DS-006

### REQ-TIME-003 "경로" 카드를 없애고 타임라인 하나로 합치기

- 상태: 대기
- 우선순위: P2 (제안)
- 등록일: 2026-11-11
- 대상: `Prototype-v2/js/app.js` `renderTimeResult` (788행~: `// 경로` 카드, `// 타임라인` 카드) / `Prototype-v2/css/style.css` `.route-legs`, `.route-leg`, `.timeline-*`

**현재 문제**
결과 화면에 "경로" 카드("② 신도림 → 강남 · 12개역" 한 줄)와 "타임라인" 카드가 따로 있는데, 같은 내용이 타임라인에도 있어 겹친다.

**요구사항**
1. "경로" 카드를 없앤다.
2. 타임라인의 탑승 단계에 노선 뱃지와 이동 역 수를 붙인다. (예: `21:03  ② 2호선 탑승 (신도림) · 12개역 이동`)
3. 환승 단계에는 갈아타는 노선 뱃지를 붙인다.
4. 카드 제목은 `타임라인` 대신 `이동 순서`로 바꾼다.

**완료 조건**
- [ ] 결과 화면에 "경로" 카드가 없다.
- [ ] 타임라인의 탑승, 환승 단계에 노선 뱃지와 이동 역 수가 보인다.
- [ ] 환승이 있는 경로(예: 신도림 → 고속터미널)에서 노선별 이동이 모두 보인다.

**참고**
- 2026-11-11 추천안으로 결정. ("4. 좋아.")
- 카드 제목 `이동 순서`는 등록 시 제안한 이름이다. 어색하면 다시 정한다.

### REQ-TIME-004 타임라인에 엘리베이터 문제를 함께 표시

- 상태: 대기
- 우선순위: P1 (제안)
- 등록일: 2026-11-11
- 대상:
  - `Prototype-v2/js/app.js` `renderTimeResult` (엘리베이터 경고 박스, 타임라인)
  - `Prototype-v2/js/time-calculator.js` `calculateDeparture`의 `timeline`, `warnings` (300행~)

**현재 문제**
위쪽 경고 박스에는 "신도림역 엘리베이터 일부 운행"이라고 나오는데, 아래 타임라인에는 "신도림역 도착 · 엘리베이터 이용"이 아무 표시 없이 나온다. 타임라인만 보고 따라가면 어디를 조심해야 하는지 알 수 없다.

**요구사항**
1. 엘리베이터에 문제가 있는 역(출발역, 환승역, 도착역)의 타임라인 단계에 상태 아이콘(REQ-DS-003)을 붙인다.
2. 그 단계 아래에 멈춘 엘리베이터 위치를 작게 보여 준다. (예: `멈춤: 8-1번 출구`, 여러 대면 `8-1번 출구 외 1곳`. REQ-ELV-004와 같은 말투)
3. 이용 불가 역이면 그 단계에 `대체역 보기` 링크를 붙인다.
4. 위쪽 경고 박스는 그대로 둔다.

**완료 조건**
- [ ] 엘리베이터 문제가 있는 역의 타임라인 단계에 상태 아이콘과 멈춘 위치가 보인다.
- [ ] 문제없는 역의 단계에는 아이콘이 없다.
- [ ] 시연 시나리오로 도착역을 고장 내고 다시 계산하면, 도착 단계에 이용 불가 아이콘과 `대체역 보기`가 보인다.
- [ ] 위쪽 경고 박스의 내용과 타임라인 표시가 서로 맞다.

**참고**
- 2026-11-11 추천안으로 결정. ("5. 좋았어.")
- 관련: REQ-ELV-004, REQ-DS-003
