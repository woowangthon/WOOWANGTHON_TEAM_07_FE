# 디자인 시스템

전역 디자인 기준입니다. 모든 화면은 이 값을 따릅니다.
값의 정의 위치: `Prototype/css/style.css`의 `:root` (11~56행)

> 아래 표는 2026-11-04 기준 프로토타입의 현재 값입니다.
> 기준을 바꾸는 지적은 맨 아래 `## 요구사항`에 `REQ-DS-xxx`로 기록하고, 반영되면 표를 갱신합니다.

## 디자인 원칙

2026-11-11 결정. 모든 디자인 판단은 이 원칙을 먼저 따릅니다.

- **주 사용자**: 사회적 약자(교통약자) 전체. 휠체어 이용자, 유모차 이용자, 고령자, 저시력자를 모두 포함한다.
  - 큰 글자, 높은 대비, 넉넉한 터치 영역을 기본으로 한다.
  - 상태는 색만으로 구분하지 않는다. (REQ-DS-003)
- **브랜드 톤**: "점자블록 옐로". 노랑 + 진한 차콜 조합으로 크고 굵고 분명하게 보여 준다. 말투는 지금처럼 친절한 "~해요"체. (REQ-DS-001)
  - 근거 1: 점자블록이 노란색이다. 교통약자를 위한 길 안내라는 서비스 의미와 바로 이어진다.
  - 근거 2: 노랑과 검정 계열은 명도 차이가 가장 커서 저시력자, 고령자가 알아보기 쉽다. 노랑 `#FFD400`과 `#111827`의 대비는 12.4:1이다.
  - 근거 3: 앱에 남은 1~8호선에는 노란색 노선이 없어 노선 색과 겹치지 않는다. (노란색이던 수인분당선은 REQ-MAP-002로 제외)
- **노랑 사용 규칙**
  - 노랑은 넓은 면(버튼 배경, 선택된 탭/칩 배경, 강조 카드 배경)으로만 쓰고, 그 위 글자와 아이콘은 `--on-primary`(차콜)로 쓴다.
  - 흰 배경 위에 노랑 글자, 노랑 얇은 선, 노랑 아이콘을 쓰지 않는다. (대비 1.4:1로 거의 안 보임)
  - 흰 배경 위에 브랜드 계열 글자가 꼭 필요하면 `--primary-text`(진한 노랑 `#8A6A00`, 대비 5.1:1)를 쓴다.
- **시연 형태**: 데스크톱의 폰 프레임 + 시연 제어판(`.desktop-stage`, `#demoPanel`)을 발표 화면으로 쓴다.
- 탈락한 브랜드 안 (참고): B안 "파랑 유지 + 노랑 포인트"(개성 약함), C안 "부드러운 버터 옐로"(대비가 약해 저시력자에게 불리).

## 요구사항

### REQ-DS-001 브랜드 색을 "점자블록 옐로"로 변경

- 상태: 대기
- 우선순위: P1 (제안)
- 등록일: 2026-11-11
- 대상:
  - `Prototype-v2/css/style.css` `:root` `--primary`, `--primary-press`, `--primary-tint`, `--indigo-tint`
  - 주 색상을 배경으로 쓰는 곳: `.btn-primary`, `.chip.active`, `.msg.user .bubble`, `.tab::before`, `.switch input:checked`
  - 주 색상을 글자/선으로 쓰는 곳: `.tab.active`, `.big-time`, `.swap-btn`, `.timeline::before`, `.timeline-item:last-child .timeline-icon`, `.form-field input:focus`, `:focus-visible` / `Prototype-v2/css/map.css` `.station-node.selected .station-label`, `.map-controls .icon-btn:focus-visible`, 우회 경로 강조(198~220행)
  - 파랑을 직접 쓴 곳: `rgba(37, 99, 235, …)` (style.css 130, 241, 321~322, 595, 1009, 1115, 1215~1216행 / map.css 70~71, 198행), `#93C5FD`(style.css 845행 `.timeline::before`)

**현재 문제**
주 색상이 파랑(`#2563EB`)이라 서비스만의 인상이 없고, 교통약자를 위한 서비스라는 의미와도 이어지지 않는다.

**요구사항**
1. 주 색상 토큰을 다음 값으로 바꿔야 한다.
   - `--primary`: `#FFD400` (노랑)
   - `--primary-tint`: `#FFF6CC` (연한 노랑)
   - `--primary-press`: 노랑보다 한 단계 진한 값 (구현 시 정하고 이 문서 색상 표에 기록)
2. 토큰을 새로 추가해야 한다.
   - `--on-primary`: `#111827` (노랑 면 위의 글자와 아이콘)
   - `--primary-text`: `#8A6A00` (흰 배경 위의 브랜드 계열 글자)
3. 노랑을 배경으로 쓰는 곳(버튼, 선택된 칩, 사용자 말풍선 등)의 글자색은 `#fff` 대신 `--on-primary`를 써야 한다.
4. 주 색상을 흰 배경 위 글자나 얇은 선으로 쓰던 곳은 노랑으로 바꾸지 않는다. `--primary-text`, `--text`, 또는 노랑 면 + 차콜 글자 조합 중 하나로 바꾼다. (위 `노랑 사용 규칙`)
5. 직접 쓴 파랑 `rgba(37, 99, 235, …)`, `#93C5FD`는 모두 토큰으로 바꿔야 한다. 필요하면 노랑 기반 토큰(예: 포커스 링, 그림자)을 추가하고 문서에 기록한다.
6. 데스크톱 배경 그라데이션(style.css 130행)의 파랑도 브랜드 톤에 맞게 바꾼다.
7. 노선 색, 한강 색(`--river`)은 바꾸지 않는다.

**완료 조건**
- [ ] `Prototype-v2/css/`에 `#2563EB`, `#1D4ED8`, `rgba(37, 99, 235` 가 남아 있지 않다.
- [ ] 주요 버튼, 선택된 칩, 사용자 말풍선이 노랑 배경에 차콜 글자로 보인다.
- [ ] 흰 배경 위에 노랑 글자나 노랑 얇은 선이 없다. (선택된 탭 이름, 큰 출발 시각, 선택된 역 이름, 입력칸 포커스 테두리 확인)
- [ ] 글자와 배경의 대비가 모두 4.5:1 이상이다. (큰 글자는 3:1 이상)
- [ ] 노선 색과 한강 색은 그대로다.
- [ ] 이 문서의 색상 표가 새 값으로 갱신되어 있다.

**참고**
- 사용자 원문: "내가 노란색을 좋아해서 노란색으로 하고 싶은데 이건 아무 이유가 없으니까..." → 접근성 근거(점자블록, 명도 대비)를 들어 A안 "점자블록 옐로"로 결정. ("A 선택지 좋다.")
- 결정 근거와 규칙: 이 문서의 `## 디자인 원칙`
- 관련: REQ-DS-002 (주의 상태색이 노랑과 겹치는 문제)

### REQ-DS-002 "일부 불가" 상태색을 진한 주황으로 변경

- 상태: 대기
- 우선순위: P1 (제안)
- 등록일: 2026-11-11
- 대상:
  - `Prototype-v2/css/style.css` `:root` `--warn`, `--warn-text`, `--warn-tint`
  - `Prototype-v2/css/map.css` `.map-legend .dot.warn`, `.metro-svg .status-dot.warn` (대체값 `#F59E0B`)

**현재 문제**
"일부 불가" 상태색(`--warn` `#F59E0B`)이 주황빛 노랑이라, 브랜드 색을 노랑으로 바꾸면(REQ-DS-001) 브랜드 강조와 주의 상태를 헷갈리게 된다.

**요구사항**
1. 주의 상태 토큰을 진한 주황 계열로 바꿔야 한다.
   - `--warn`: `#EA580C` (점, 막대 등 그래픽용. 흰 배경 대비 3.6:1)
   - `--warn-text`: `#C2410C`
   - `--warn-tint`: `#FFF7ED` (`--warn-text`와 대비 4.9:1)
2. `map.css`의 대체값 `#F59E0B`도 함께 바꾸거나 지운다.
3. 정상(`--ok`), 이용 불가(`--bad`) 색은 바꾸지 않는다.

**완료 조건**
- [ ] `Prototype-v2/css/`에 `#F59E0B`, `#B45309`, `#FEF3C7`이 남아 있지 않다.
- [ ] 노선도 상태 점, 범례, 상태 뱃지, 요약 카드, 역 목록 왼쪽 막대, 대체역 안내 박스의 "일부 불가"가 진한 주황으로 보인다.
- [ ] 브랜드 노랑과 "일부 불가" 주황이 나란히 있어도 구분된다.
- [ ] 상태 뱃지 글자와 배경 대비가 4.5:1 이상이다.

**참고**
- 주황(`--warn`)과 빨강(`--bad`)은 색약 사용자에게 비슷해 보일 수 있다. 그래서 REQ-DS-003(색만으로 구분하지 않기)과 함께 적용한다.
- 관련: REQ-DS-001, REQ-DS-003

### REQ-DS-003 엘리베이터 상태를 색만으로 구분하지 않기

- 상태: 대기
- 우선순위: P1 (제안)
- 등록일: 2026-11-11
- 대상:
  - `Prototype-v2/css/style.css` `.status-pill::before`, `.summary-card`, `.station-row.warn`, `.station-row.bad`
  - `Prototype-v2/css/map.css` `.map-legend .dot`, `.metro-svg .status-dot`
  - `Prototype-v2/js/metro-map.js` 상태 점 생성(465행 `status-dot`), 상태 갱신(632행)
  - `Prototype-v2/index.html` `.map-legend`

**현재 문제**
정상 / 일부 불가 / 이용 불가가 초록, 주황, 빨강 점으로만 구분된다. 색약 사용자나 저시력 사용자는 상태를 알아보기 어렵다. 특히 노선도의 상태 점은 반지름 3.4~3.8 지도 단위로 매우 작다.

**요구사항**
1. 상태마다 색과 함께 모양(아이콘)을 달리해 보여야 한다. 색을 빼고 흑백으로 봐도 세 상태가 구분되어야 한다.
   - 모양은 구현 시 제안해 사용자 확인을 받는다. (예: 정상 ✓, 일부 불가 !, 이용 불가 ✕)
2. 적용 위치: 노선도 역 상태 표시, 노선도 범례, 상태 뱃지(`.status-pill`), 엘리베이터 목록 행.
3. 노선도 상태 표시는 기본 줌에서도 알아볼 수 있는 크기여야 한다.
4. 범례도 같은 모양을 써서 지도와 일치해야 한다.

**완료 조건**
- [ ] 화면을 흑백(grayscale 필터)으로 봐도 세 상태가 모양으로 구분된다.
- [ ] 노선도, 범례, 상태 뱃지, 엘리베이터 목록에서 같은 상태는 같은 모양이다.
- [ ] 노선도 기본 줌(375px 폭)에서 상태 표시를 알아볼 수 있다.
- [ ] 역 탭, 우회 경로 강조 등 노선도 기존 기능이 그대로 동작한다.
