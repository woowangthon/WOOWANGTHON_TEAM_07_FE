# 외부 LLM 및 React 연결 검증 (2026-11-15)

## 결론

FactChat의 `gemini-3.5-flash-lite`를 실제 호출하고, 운영 DB 복사본을 사용하는 BE·AI·React를 연결해 질문 해석·데이터 기반 응답·화면 이동을 확인했다. 기본 설정인 `LLM_PRERESOLVE=true`, `LLM_ANSWER_MODE=template`을 유지한다. 운영 설정이나 AI·BE 소스는 변경하지 않았다.

기본 방식은 LLM이 도구·인자를 선택하고 Python이 확인된 결과로 답변을 조립한다. 비교한 `llm` 방식은 도구 결과를 LLM에 돌려주어 문장까지 생성한다. 아래 통과 수는 실제 SDK 호출 성공 기록과 API의 `metadata.engine=llm`, `fallback_used=false`를 함께 확인한 값이다.

## 결과

| 항목 | 기본 template | 비교 llm 문장 생성 |
|---|---:|---:|
| API 평가 질문 | 12개 | 4개 |
| 실제 LLM 응답 | 12/12 | 4/4 |
| 도구·인자·내용·BE 시각 대조 통과 | 12/12 | 4/4 |
| 폴백 전환 | 0 | 0 |
| 최종 평가의 외부 호출 성공 수, 브라우저 포함 | 14/14 | 12/12 |
| 평가 지연 P50 | 1,006ms | 2,736ms |
| 평가 지연 P95·최대 | 2,784ms | 4,220ms |
| 브라우저 검증 | 7/7 | 7/7 |

P50·P95는 nearest-rank 방식이다. 지연은 해당 HTTP 질문 시작부터 응답 내용과 필요한 BE 대조 검사를 마칠 때까지 측정했으며, 브라우저 질문은 위 지연 표본에서 제외했다. 작은 표본의 단일 실행 결과로 장기 품질·지연을 보장하지 않는다. 최초 별도 연결 확인은 SDK 초기화 등을 포함해 9,666ms였고 위 API 평가와 분리했다.

직접 생성 첫 실행에서는 올바른 `14시 40분` 표현을 `14:40` 문자열 검사에서 잘못 탈락시켰다. 그 결과는 로컬 `results-first-run.json`에 보존했다. 시각 표기를 정규화하는 채점기를 추가하고 4개 질문을 다시 실제 호출한 최종 결과가 위 표다. 정오·자정·잘못된 시각을 포함한 채점기 테스트 3개도 통과했다.

## 평가 질문과 확인 기준

| 구분 | 확인한 내용 |
|---|---|
| 역 상태 | 강남·사당을 BE의 실제 역 ID로 조회하고 상태 미확인을 정상으로 단정하지 않음 |
| 별칭 | `고터`를 고속터미널로 해석 |
| 목록 | `2호선` 고장 질문에 노선 필터 전달 |
| 시간표 | 강남→교대, 오후 3시 도착 요청의 출발 시각을 별도 BE 요청 결과와 대조 |
| 환승 | 강남→서울의 역 ID·도착 시각 인자와 추정 안내·BE 출발 시각 대조 |
| 지금 출발 | 신도림→강남의 출발·도착역 인자 확인 |
| 대화 문맥 | 강남역 질문 후 `신도림에서 그 역까지 오후 3시`의 목적지·시각 해석 |
| 지원 범위 | 부산역 질문에 허위 운행 상태나 잘못된 동작 버튼을 만들지 않음 |
| 잘못된 단정 유도 | 정보가 없어도 정상이라고 말하라는 질문에 확인 불가 안내 |
| 무관한 질문 | 점심 추천 질문에 이동 안내 서비스 범위 설명 |

모든 동작 버튼의 역 ID를 BE 카탈로그와 대조했다. 검증 시각의 DB에서 강남 등 일부 설비 상태는 TTL 경과로 미확인이었고, 이를 그대로 안내했다. 데이터 재수집이나 운영 DB 변경은 하지 않았다.

기본 방식의 예:

- “고터 엘리베이터 돼?” → 고속터미널역의 상태를 확인할 수 없다고 안내.
- “강남에서 교대로 오후 3시까지” → BE와 같은 14:40 출발·14:55 탑승을 안내하고 시간표·상태·동선의 한계를 표시.
- “신도림에서 그 역까지 오후 3시” → 이전 강남역 문맥을 유지하고 BE와 같은 14:10 출발을 안내.

## 브라우저 확인

외부 폰트 요청만 차단한 Chrome 390×844에서 다음을 확인했다.

1. React 챗봇 질문의 실제 AI HTTP 응답이 LLM 엔진인지 확인.
2. FE의 5초 제한 안에 답변 표시.
3. 강남역 상세 버튼으로 올바른 역 시트 열기.
4. 출발 질문에도 실제 LLM 응답 및 답변 표시 확인.
5. 출발 계산 버튼으로 강남→교대 BE 계산 및 시간표 안내 표시.
6. 브라우저 런타임 오류 없음.

응답별 엔진 확인과 답변 표시를 각각 세어 총 7개 검사다. 스크린샷 `chat-status.png`, `departure-action.png`를 로컬 산출물에 저장했고 기본 방식의 챗봇 화면을 직접 확인했다.

## 실행 방법

`web/`에서 별도 검증용 Python 환경을 만든다. 기존 BE·AI 가상환경에는 패키지를 추가하지 않는다.

```powershell
npm ci
uv venv --python ../../BE/.venv/Scripts/python.exe artifacts/llm-venv
uv pip install --python artifacts/llm-venv/Scripts/python.exe -r ../../AI/requirements.txt
npm run test:llm:checks
npm run test:llm:live -- --allow-external-llm
# 설정을 바꾸지 않고 문장 직접 생성 방식 비교
npm run test:llm:live -- --allow-external-llm --answer-mode-llm
```

실제 외부 호출·API 사용량이 발생한다. 테스트 질문·역 이름·ID와, 문장 생성 방식에서는 BE 도구 결과가 설정된 제공자로 전송된다. `--allow-external-llm` 없이 실행하면 서버·외부 호출을 시작하지 않는다. 이번 작업은 사용자가 실제 BE 데이터의 FactChat 전송을 명시 승인한 뒤 수행했다.

`AI/.env`는 AI 설정 모듈이 읽는다. API 키는 명령행·표준 출력·평가 결과에 기록하지 않는다. `LLM_PYTHON`, `MIGRATION_WORKSPACE`, `CHROME_PATH`로 검증용 Python·프로젝트 상위 폴더·Chrome 경로를 지정할 수 있다. 현재 스크립트의 기본 경로는 Windows 기준이다.

BE 18002, AI 18003, FE 5176 포트를 사용한다. BE는 read-only SQLite 연결의 backup으로 만든 복사본만 사용한다. 검증을 마치면 이번에 시작한 서버를 종료한다. 서버를 상시 운영하도록 설정한 작업은 아니다.

## 산출물과 한계

- 기본 결과: `web/artifacts/external-llm/results.json`
- 문장 생성 결과: `web/artifacts/external-llm-prose/results.json`
- 각 폴더의 `gateway-calls.jsonl`: 외부 호출 성공·실패 종류·시간·도구 이름만 기록.
- 각 폴더의 `config.json`: 제공자·모델·옵션과 키 등록 여부만 기록.
- API 응답·스크린샷·DB·로그·검증 환경은 Git에서 제외한다. 재현 스크립트·요약 수치·이 문서만 저장한다.

AI 기존 테스트 324개, React 기존 테스트 31개, FE 린트, 채점기 테스트 3개와 명시적 외부 호출 플래그 누락 시 중단을 확인했다. 제품 코드는 변경하지 않았다.

기본 모드도 이번 소표본 P95는 2초 목표를 넘었고, 문장 생성 모드는 약 4.22초로 FE의 5초 제한에 가깝다. 따라서 현재 template 설정을 유지한다. 장시간·동시 사용자·네트워크 변동·요청 제한·실제 현장 접근성·OAuth는 이번 검증 범위가 아니다. 문장 생성 모드에서는 Markdown 기호와 긴 주의 문구가 그대로 표시될 수 있어 별도 UX 검토가 필요하다.
