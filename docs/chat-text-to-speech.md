# AI 챗봇 답변 소리로 듣기

REQ-CHAT-005의 React 구현이다. 저시력 사용자, 이동 중 화면을 보기 어려운 사용자가 답변을 들을 수 있게 한다. 화면 읽기 프로그램을 대체하지 않으며, 화면의 답변과 경고는 계속 표시한다.

## 동작과 접근성

기본 설정은 **말로 물었을 때만**이다. 음성 질문의 답변만 자동으로 읽고 글자 질문과 처음 여는 환영 문구는 자동으로 읽지 않는다. **항상**은 새 질문의 답변을 자동으로 읽는다. **끄기**는 자동 읽기를 끈다. 세 모드 모두 답변별 **답변 듣기** 버튼으로 수동 재생할 수 있다. 설정은 `localStorage`의 `chat-speech-mode`에 모드 문자열만 저장하며 질문·답변·음성은 저장하지 않는다. 저장소가 차단되어도 현재 세션에서는 설정할 수 있다.

읽는 중에는 해당 버튼이 **멈추기**로 바뀌며 접근성 이름은 **읽기 멈추기**이다. 버튼은 기본 HTML button이므로 키보드 Enter/Space로 작동한다. `aria-pressed`가 상태를 전하고 최소 터치 영역은 기존 `--tap-min`(44px) 토큰을 쓴다. 새 발화는 이전 발화를 취소한다. 반복 클릭은 중단한다. 브라우저 탭을 숨기거나 컴포넌트를 제거해도 중단한다. 새 질문 제출·글자 입력·마이크 시작·앱 내부 탭 이동은 통합 화면이 `stop()`을 호출해야 한다. 읽기 속도·음량은 브라우저 기본값이며 기기의 음량 조절을 사용한다.

화면 읽기와 시스템 TTS가 동시에 들릴 수 있으므로 설정에 끄기 안내를 둔다. 화면 읽기 프로그램 실행 여부를 추측하거나 탐지하여 설정을 강제로 바꾸지 않는다. 기본 모드도 사용자의 마이크 질문 이후에만 읽는다. [WCAG 2.2의 음성 제어 기준](https://www.w3.org/TR/WCAG22/#audio-control)은 자동 음성의 중단 수단을 요구하므로 답변마다 중단 버튼을 제공한다. 이 구현만으로 서비스 전체의 WCAG 준수를 선언하지 않는다.

## 목소리와 개인정보

브라우저의 `speechSynthesis`와 `SpeechSynthesisUtterance`를 사용한다. 마이크 접근은 하지 않으며 앱이 별도의 음성 합성 API 요청을 보내지 않는다. 그러나 이는 반드시 기기 안에서만 처리된다는 뜻은 아니다. [MDN의 localService 설명](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisVoice/localService)에 따르면 목소리는 로컬 또는 원격 합성 서비스가 제공할 수 있다. 브라우저가 보고한 `localService=true` 한국어 목소리를 우선하고, 없으면 기본 한국어 목소리, 그 다음 첫 한국어 목소리를 선택한다. 원격 목소리는 답변 글을 외부로 보낼 수 있고 연결 상태와 서비스 정책의 영향을 받는다. 앱은 실제 처리 사업자·보관 기간·오프라인 작동을 보장하지 않는다.

설정 UI에 **기기의 시스템 TTS를 사용하며 음성 처리 방식은 브라우저와 선택된 목소리에 따라 다르고 답변 글이 외부 서비스로 전송될 수 있음**을 고지한다. 로컬 목소리만 강제하는 기능이나 사용자가 목소리를 직접 선택하는 기능은 포함하지 않는다. 민감한 내용을 듣기 전에 브라우저와 운영체제의 음성 서비스 설정을 확인할 수 있다.

[MDN getVoices 문서](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis/getVoices)에 따른 목소리 목록을 조회하고 `voiceschanged` 때 다시 조회한다. 초기 목록이 비어도 미지원으로 단정하지 않는다. API 자체가 없으면 미지원 안내를, 한국어 목소리가 아직 없으면 대기 및 기기 설정 확인 안내를 표시하고 답변 듣기 버튼은 숨긴다. 한국어를 설치하지 않았거나 브라우저가 노출하지 않으면 계속 사용할 수 없다. API 지원과 한국어 음성 설치는 별개다.

## 읽기용 글과 안전 정보 보존

`toSpeechText()`는 HTML 파서를 사용하지 않는 평문 변환이다. Markdown 제목·강조·링크 장식을 정리하고 링크의 설명 글은 보존한다. 이모지를 제거하고 화살표와 가운데점을 말로 바꾼다. 시각 `20:53`은 `오후 여덟 시 오십삼 분`처럼 변환하며 ISO 수집 시각의 날짜와 시간대도 남긴다. 노선 번호·설비 번호·출구 번호·고장 경고·확인 불가·수집 시각·이용 가능 보장 불가 문구를 삭제하지 않는다. `<역>`이나 `A < B` 같은 원문을 태그로 간주해 없애지 않는다.

입력은 **답변 평문과 카드의 의미 있는 요약**이어야 한다. 카드 HTML을 직접 넘기면 태그가 그대로 읽힐 수 있다. 버튼 이름과 추천 질문은 포함하지 않는다. 카드 요약은 화면 운행 현황과 동일한 데이터·집계 함수를 사용하고 경고·제약·수집 시각을 포함해야 한다. 이 모듈은 서버 카드 구조나 운행 현황을 다시 계산하지 않는다. 외부 LLM 문장을 신뢰성 검증 없이 안전 안내로 승격하지 않으며 화면의 불확실성을 음성에서도 보존한다.

숫자의 모든 문맥(열차 번호·소수점·고유명사 등)을 한국어 발음으로 재작성하지 않는다. 임의 변환으로 의미가 달라질 수 있기 때문이다. 같은 글도 실제 발음은 선택된 한국어 목소리에 따라 다르다. 긴 답변을 자르지 않으므로 경고가 누락되지 않지만 브라우저별 긴 발화 중단 문제는 기기 확인이 필요하다.

## 통합 API

`web/src/views/chat/voice/tts/index.ts`에서 내보낸다.

```tsx
const speech = useChatSpeech()
// 답변 도착 시 통합 화면에서 한 번만 호출한다. 초기 환영 문구는 제외한다.
if (speech.mode === 'always' || (speech.mode === 'voice' && voiceOrigin)) {
  speech.speak(messageKey, answerPlainText)
}
// 설정 위치
<SpeechSettings speech={speech} />
// 각 봇 답변. 키는 고유하고 안정적인 숫자여야 한다.
<SpeechControls messageKey={messageKey} text={answerPlainText} speech={speech} />
```

훅은 `supported`, `ready`, `speakingKey`, `mode`, `setMode`, `speak`, `stop`, `error`를 반환한다. `speak` 자체는 mode를 검사하지 않아 끄기에서도 수동 읽기를 지원한다. 비동기 답변을 자동으로 읽을지는 통합 화면이 결정한다. 중단 이후 늦게 도착하는 기존 답변을 자동 재생하지 않도록 통합 화면도 질문의 세대·취소 상태를 확인해야 한다. 훅은 취소된 과거 utterance의 지연된 종료·오류 이벤트를 무시한다. 브라우저의 `cancel()`은 해당 페이지의 음성 큐를 비우므로 다른 기능이 같은 페이지에서 합성을 시작한다면 단일 소유자로 조정해야 한다.

## 검증과 남은 확인

`npm test -- src/views/chat/voice/tts/tts.test.tsx`로 fake `speechSynthesis`/utterance를 주입해 검증한다. 실제 음성을 출력하거나 원격 음성 API를 호출하지 않는다. 초기 자동 재생 없음, 한국어 지연 로드, 로컬 음성 우선, 과거 이벤트 무시, 설정 저장, 끄기에서 수동 재생, 탭 숨김·언마운트 취소, 오류 복구, 미지원 안내, 반복 클릭, 시각과 안전 문구 보존을 확인한다.

실제 기기의 한국어 발음·음질·볼륨, 자동 읽기의 사용자 활성화 제한, 모바일 백그라운드 동작, TalkBack/VoiceOver와의 동시 사용, 원격 목소리의 실제 데이터 처리와 통합 후 브라우저 배치는 별도 확인 대상이다. 브라우저가 자동 재생을 거부하면 오류 안내와 수동 답변 듣기를 이용한다. 목소리 목록·이벤트·오류 콜백이 정상 작동하는지 역시 브라우저 구현에 달려 있다. 단위테스트 결과를 실제 음성 품질 검증으로 취급하지 않는다.
